  preventing interrupted work from being attributed to a later resumed turn.

## [0.22.0] - 2026-08-15

### Changed

- Concurrent OpenCode runs must use distinct sessions. OpenCode events carry session identity but no turn identity, so overlapping writers and delayed background continuations on one session cannot be separated reliably and remain an explicitly unsupported environmental constraint — OPENCODE-006, ENG-018
- **Breaking:** tmux-play now requires tmux 3.3 or newer so attached-client layout reconciliation can use the post-negotiation `window-resized` hook — TMUX-044

### Fixed

- An asynchronous Gemini child-process launch error now terminates through the normalized event stream as a non-recoverable `error` followed by `done`, rather than escaping as an unhandled promise rejection that can terminate the consumer process — GEMINI-003, TADAPT-007
- Codex and Gemini now treat an empty `resume` value consistently as a fresh run, using a generated non-empty correlation identifier; Codex also attributes the fresh thread's first cumulative usage snapshot instead of discarding it as an unseen resumed-thread total — CODEX-005, GEMINI-007, TADAPT-015, TADAPT-025
- OpenCode now treats an empty `resume` value as a fresh session for both backend dispatch and causal usage accounting, preserving the created-session attribution fallback instead of silently omitting an otherwise attributable token report — OPENCODE-021, TADAPT-040
- OpenCode usage no longer anchors on activity a run did not submit. A resumed root session is not exclusive: a background task started by an earlier invocation injects its result there as a fresh prompt, and a concurrent caller's own prompt can stream first — either could precede the run's own message and be taken as its causal boundary, silently billing another party's work as this run's. The adapter now proves ownership from the dispatch itself, anchoring on the message whose text is the prompt it submitted — not on an assistant repeating that text back, which would otherwise look like a second, contradictory proof and silently drop the run's whole token report. Ordering now stands in for that proof only for a run that created its root session under the documented single-writer constraint; a resumed run may not fall back and omits `usage.tokens` entirely per ENG-031 rather than bill work it cannot show is its own. The event stream is also established before the prompt is dispatched, since the endpoint replays nothing and a run that missed its own prompt would have had only foreign messages to reason from — OPENCODE-021, TADAPT-040
- Rapid terminal resizing can no longer leave weighted tmux-play columns at an earlier width. Background resize workers now serialize per session, reject superseded visible-pane generations, verify the final negotiated width before retiring, and reconcile each rebuilt pane shape immediately. Each worker also reads that width itself: `run-shell` expands formats in the command it is given, so a bare `#{window_width}` was substituted once when the hook fired and baked that instant's width into the worker — both sides of its verification compared the same constant, and a worker that reached the lock after a newer one repainted the older width unchallenged. Escaping the format lets it reach the worker's own shell, so a late worker resizes to the width the window holds when it runs. The attached-client coverage now parks a stale worker before it takes the reconcile lock rather than inside its resize, since blocking after acquisition holds the lock and makes the newest width write last no matter what — the ordering the test exists to provoke could not occur — TMUX-044, TTMUX-035

### Added

- tmux-play now accepts dot-delimited player IDs and complete per-call `settings` replacements for model, effort, instruction, and permissions. Model and effort can explicitly select a concrete value or the provider default; Codex and Gemini can reset defaults on fresh or resumed calls, Claude and OpenCode can use default effort beside a concrete resumed model but reject their unrestorable resumed default model, OpenCode clears omitted resumed permissions, and resumed Kimi fails closed because ACP cannot restore model, effort, or permission defaults. The `@sublang/cligent/tmux-play` entry point exports `AgentCallSettingsError` and `isAgentCallSettingsError()` so an embedding caller can distinguish those failures while retaining the original diagnostic and cause. It also exports a managed interactive lifecycle: a caller-supplied tmux-safe public session ID, prepared activation/attach or cancellation, stable-pane and bounded readiness checks, explicit launcher work-directory ownership backed by a matching launcher-ownership marker, graceful shutdown request/acknowledgement with forced fallback, initialized-or-restored runtime injection, pre-turn write-ahead, terminal-aware post-turn settlement, buffered Captain replies that still release after successful settlement during shutdown, session-runner tmux isolation before embedding-owned initialization, distinct SIGHUP and embedding-request reasons, and shutdown serialized behind the complete transaction. Auto theme detection follows the public eventual-attachment intent instead of the internally detached preparation step, and caller-supplied work directories are never recursively removed. An empty player roster now uses the same runtime and managed lifecycle as a Boss/Captain-only session: the launcher creates one full-width Captain pane and no player log tails, while empty manifests, visibility records, presentation, and reply settlement remain valid; nonempty rosters still cannot hide every player. Stock nonempty-roster tmux-play launch, session, and runtime behavior and generic `Cligent` option merging remain unchanged except that stock session mode now routes SIGHUP through the ordinary TMUX-026 shutdown lifecycle — IR-048, TMUX-005, TMUX-026, TMUX-028, TMUX-029, TMUX-047, TMUX-074, TMUX-080, TMUX-081, TMUX-093, TMUX-094, TTMUX-014, TTMUX-073, TTMUX-080, TTMUX-083, TTMUX-096, TTMUX-097

### Changed

- **Breaking:** `DonePayload.usage` now requires only the independently observed `toolUses` count and replaces `tokenAvailability`, `inputTokens`, `outputTokens`, `totalCostUsd`, and the unreleased `breakdown` / top-level `records` shape with optional `tokens` and provenance-bearing `cost` reports. `tokens.totals` carries inclusive input and output sides, so cache reads/writes and reasoning are subsets rather than double-counted addends; absence means unreported and a present zero is measured. Every report says whether it covers the complete causal agent tree or an exact partial scope, and optional per-rate-card records sum to those totals. Claude Code publishes complete per-model records and agent-estimated cost; Codex publishes an exact partial root-thread delta without pretending the requested model was observed; Gemini cross-validates prompt-free per-response telemetry for complete thinking/cache/subagent records; OpenCode verifies the live server's exact conformance version, suppresses its hidden title request, records only pinned causal task/compaction boundaries once per canonical step, downgrades retries or unproved internal/background work, and labels its catalog cost an agent estimate; Kimi publishes no token or cost report because the pinned ACP runtime exposes none. Cligent still applies no rate table, and callers must account for absent model/request/cache-tier/tool dimensions before calculating price — DR-014, IR-050, ENG-031, TENG-022, TADAPT-040

### Fixed

- OpenCode runs no longer hang without a terminal event. The adapter supplied its own `messageID` when submitting a prompt so it could anchor causal usage attribution, but OpenCode mints message identifiers in its own format; the foreign identifier left the session permanently busy, so a run streamed output and never reached `done`. The adapter now submits no identifier and observes the one OpenCode assigns — the root session's user message, or the `parentID` its first root assistant message names — which restores termination while keeping per-request attribution and coverage intact — OPENCODE-021
- Prepared managed tmux attachment now accepts an abort signal and a synchronous native-client handoff callback. Abort remains owned through activation or detached coordination cleanup, retires the child before rejecting, keeps the signal reason primary, and reports every cleanup defect. Managed session shutdown likewise aggregates secondary lifecycle and cleanup failures instead of hiding them behind the initiating turn failure — IR-048, TMUX-094, TTMUX-097
- Claude Code runs now report the tokens of the whole run rather than of the main conversation loop alone. `result.usage` counts only the main loop, so a run that spawned subagents understated its spend — measured at 50% of input and 63% of output on one such run — while the same message's `result.modelUsage` carried the complete per-model accounting all along. The nested report is now derived only from that complete map, includes inclusive output and one record per model, and omits tokens instead of promoting the narrower fallback when the map is malformed; the runtime's whole-run and per-model cost values are preserved as explicit agent estimates — CLAUDE-011, CLAUDE-012, IR-049, IR-050
- Claude Code emits exactly one `init` event per run, from the handshake. Claude Code sends `system` messages throughout a run for hook lifecycle, compaction, retries, and status notices, and the adapter restated `init` for each one — 36 on one measured run — with every restatement after the first replacing the run's real tool list with an empty one. The handshake is now identified by its `subtype: 'init'` rather than by arriving first, because notices also precede it: a run with a `SessionStart` hook configured emits four of them before the handshake — CLAUDE-003, IR-049

- Codex turns no longer report the whole thread's accumulated tokens as the turn's own. `turn.completed` carries the thread-cumulative total and a resumed thread seeds it from its rollout, so every turn after the first overstated usage — by roughly the whole conversation by the tenth turn. The adapter now reports an exact partial root-thread difference against the previous snapshot, treats a thread it started as beginning from zero, and omits tokens rather than publishing a cumulative figure when it resumes a thread it holds no baseline for or when a snapshot decreases because the accounting restarted; it no longer labels that record with a merely requested model — CODEX-015, CODEX-017, ENG-018

## [0.20.0] - 2026-08-12

### Changed

- **Breaking:** `DonePayload.usage` now requires `tokenAvailability: 'reported' | 'unavailable'`, so a measured zero is no longer externally identical to missing upstream accounting. All built-in adapters set `reported` only when complete finite non-negative integer input and output counters are supplied (explicit zero remains reported) and every present mapped cache or reasoning counter is valid; absent optional cache counters contribute zero, while malformed present counters make accounting unavailable. Cache-exclusive providers fold cache reads and writes into `inputTokens` exactly once; Codex preserves its cache-inclusive `input_tokens` and validates canonical `cached_input_tokens` / `cache_write_input_tokens` without double-counting; OpenCode folds canonical nested cache reads and writes into input and its disjoint reasoning counter into output exactly once. Gemini preserves cache-inclusive `StreamStats.input_tokens`, validates its `cached` and uncached `input` details, maps canonical `tool_calls`, and treats any unpartitioned difference between `total_tokens` and `input_tokens + output_tokens` as unavailable instead of estimating whether it was thinking output or tool-use-prompt input. Malformed optional Kimi usage now degrades to unavailable accounting without changing a valid prompt stop status; unconsumed thought details are ignored and null optional caches remain absent. Missing accounting and synthesized error, interruption, and exhaustion paths remain unavailable without token estimation, while independently known `toolUses` from observed or valid provider-reported counts survives either state. The shared formatter prints `tokens: unavailable` instead of numeric placeholders and defensively treats persisted pre-discriminator events as unavailable. This is an additive serialized-event field but a required TypeScript producer change: custom adapters and fixtures constructing `DonePayload` must add the discriminator, while consumers must branch on it before arithmetic or rendering; readers ingesting older stored events should interpret an absent field as unavailable — DR-002, IR-046, ENG-013, ENG-019, ENG-027, KIMI-005, TENG-019, TADAPT-033, #35
- **Breaking:** OpenCode now rejects every explicitly present `allowedTools` or `disallowedTools` option, including empty arrays, before loading its SDK. OpenCode 1.18.13 deprecates prompt `tools` as an independent control and converts the boolean map into persistent session permission rules; because those session rules replace prior rules and participate in last-match-wins evaluation after native agent rules, `allowedTools: ['bash']` could override an explicit `shellExecute: 'deny'` and the rewritten permissions could affect later resumed calls. The adapter, direct permission mapper, and exported compatibility wrapper no longer emit or accept that unsafe prompt field. Callers must omit both lists or choose an adapter with an exact tool-registry filtering surface — DR-010, IR-042, OPENCODE-013, OPENCODE-015, TADAPT-027, TADAPT-029

### Fixed

- OpenCode liveness now distinguishes root-session output from run-owned session-tree progress: fresh child and grandchild sessions are learned from lifecycle events, resumed descendants are discovered recursively before prompt dispatch, every explicitly tagged descendant event restarts the inactivity budget while ordinary child conversation remains filtered, and permission asks are answered through the native child session instead of being dropped or misrouted. A caller-supplied resume identifier rejected before prompt dispatch is no longer reissued as backend-confirmed continuity, allowing `Cligent` to clear the stale value and create a fresh session on the next run. The inactivity watchdog counts only time actively awaiting SSE, so untagged workspace-global noise cannot keep a silent run alive and downstream consumer backpressure cannot time out a buffered healthy event. Caller interruption starts the idempotent backend abort before promptly delivering the adapter's resumable `done` within the engine drain window, then bounds the retained cancellation during cleanup instead of withholding continuity for up to ten seconds. Every OpenCode-synthesized error terminal also preserves a backend session identifier already observed. The internal event formatter keeps its defensive unavailable-token behavior and unit regression, but it is no longer misrepresented as part of the public engine spec surface — IR-042, IR-043, OPENCODE-006, OPENCODE-011, OPENCODE-018, OPENCODE-020, TADAPT-012, TADAPT-035, TADAPT-037
- OpenCode runs can no longer occupy a headless concurrency slot forever when the global SSE connection and server stay alive but the active session stops emitting events. `OpenCodeAdapter` now enforces a finite, configurable `eventInactivityTimeoutMs` (five minutes by default), restarted only by events relevant to the current session — explicitly foreign multiplexed traffic does not postpone it, and long deadlines are chunked safely below host timer ceilings. On expiry it cancels the pending read and performs a bounded SDK status query: a missed idle event yields an explicit recoverable diagnostic and successful terminal outcome, while busy/retry state is aborted and a failed or hung status query produces its own non-recoverable diagnostic after a bounded cleanup attempt. Every timeout message identifies the session, last relevant event, elapsed/deadline timing, managed/external server state, and query/abort result. Pending iterators, SDK clients, session work, and managed servers are released on every path; dispatch failures return eagerly started SSE iterators and unregister their abort listeners, while rejected close or shutdown calls cannot suppress later cleanup and instance disposal carries the run working directory. Legacy create, prompt, status, and abort requests consistently scope the same working directory through the generated SDK query envelope. External-mode caller abort also cancels prompt dispatch and aborts an already-created session, captures cleanup ownership from a concurrently settled run result, wins over a simultaneously ready terminal event, and emits exactly one terminal `done`. Caller interruption initiates the known session abort before the interrupted terminal, retains bounded cancellation and iterator cleanup after delivery, and only then begins managed-child shutdown; an owned child that ignores `SIGTERM` is escalated to `SIGKILL`. Canned short-deadline coverage spans all branches, and a credential-free real managed-server probe verifies status recovery and process cleanup without a multi-minute test — OPENCODE-018, IR-043, TADAPT-035
- OpenCode headless runs can no longer wait forever for a permission answer no interactive client exists to provide. `permissions: { mode: 'auto' }` now reproduces native `--auto`: configured rules are evaluated first, explicit denies remain authoritative, no last-match-wins session wildcard is appended, and only surviving asks are answered `once` without exposing an interactive `permission_request`. Each successful automated reply now emits one namespaced `opencode:permission_decision` audit event with native request, permission-scope, and tool correlation; failed, timed-out, aborted, and non-auto replies emit no such event. OpenCode labels that auto posture dangerous because those asks — including `external_directory` requests — may be approved without a human; `writablePaths` remains ambient reporting rather than confinement, and the OpenCode process retains its host filesystem authority. Explicitly supplied portable capability levels still compose as rules, while omitted levels preserve provider and user configuration. Outside auto, residual or unknown asks are emitted and rejected fail-closed. Missing identifiers, absent or failed response APIs, SDK errors, and five-second response timeouts terminate diagnostically with correlation details. The SSE and permission waits now use one re-armed control waiter instead of attaching a reaction to run-lifetime promises per event, eliminating event-count-proportional retention; caller abort and reply timeout still cancel underlying response and SSE I/O. Managed teardown sends `SIGTERM` before bounded SDK cleanup and escalates to `SIGKILL` after a bounded grace if the server remains alive. Canonical v1/v2 fixtures cover native-rule preservation, once/reject routing, audit correlation, correlation cleanup, high-volume streaming, transport cancellation, and resistant-child teardown, while the real managed-mode leg requests an exact shell command under an explicit `bash: ask` rule to prove a native ask was answered `once` before the absolute `/tmp` write succeeds without an interactive request, denial, error, or harness timeout — IR-042, OPENCODE-007, OPENCODE-008, OPENCODE-020, TADAPT-037
- The OpenCode adapter now correlates streamed content with each message's `user` or `assistant` role before emitting normalized output. OpenCode replays the submitted prompt on its shared SSE stream as an ordinary user text part, and the adapter previously discarded the role-bearing `message.updated` envelope, so callers received that prompt again as assistant `text`. Text, deltas, and reasoning with a message id now wait when necessary for their role: assistant content is released in stream order, user content is suppressed, and unresolved identifier-bearing content fails closed at terminal completion. Legacy events without a message id retain their prior normalization, and legitimate assistant output remains untouched even when it exactly matches the prompt — IR-044, OPENCODE-017, TADAPT-034
- OpenCode reasoning deltas no longer masquerade as assistant output or duplicate the settled `thinking` stream. Canonical v1 sibling deltas and explicit v2 text/reasoning events are classified directly; generic v2 deltas wait for their `partID` to resolve to a text, reasoning, or non-content part, and unknown types fail closed instead of becoming `text_delta` or blocking later output. `textID` and `reasoningID` correlate explicit deltas with settled parts, interleaved deltas retain stream order even when metadata resolves in reverse, and removed parts or owning messages release their queued payloads and state. Text deltas remain ordered output, reasoning deltas are suppressed in favor of settled snapshots, user deltas remain filtered by message role, exact duplicate settled snapshots emit once, and a settled text snapshot that exactly repeats its part's emitted deltas is suppressed so consumers reconstruct the answer once — IR-045, OPENCODE-019, TADAPT-036

## [0.19.0] - 2026-08-07

### Added

- `CaptainRunResult` now carries the Captain call's `resumeToken`, in parity with `PlayerRunResult`. The tmux-play runtime already captured the token every `Cligent.run()` terminal `done` reported and passed it through on player results, but `callCaptain` dropped it when assembling its result, so a Captain that wanted to hand a control call's backend session to a later `CallCaptainOptions.resume` had no way to learn the token it needed. When a Captain call's terminal `done` carries a `resumeToken`, the returned `CaptainRunResult` (and the `captain_finished` record built from it) now exposes that token; when the terminal `done` carries none, the field is omitted, exactly as on player results — TMUX-033
- A turn-scoped conversational reply surface for custom Captains: `CaptainContext.emitReply(text)` emits one `captain_reply` record that the tmux presenter renders in the Boss/Captain pane as ordinary Captain prose — the same glow Markdown pipeline and colored `captain> ` speaker prefix as visible Captain speech — where `emitStatus` could only produce the bracketed `[status]` operational line that bypasses Markdown and reads as telemetry rather than as the Captain talking. The surface is deliberately minimal: text only, no options, no visibility parameter. It accepts work until the runtime resumes from `handleBossTurn`; a context used later rejects before emitting, while a reply accepted earlier drains ahead of the pre-terminal fence, so no `captain_reply` can trail its turn's terminal record. `captain_reply` is a block boundary like a complete `text` event, flushing any open streamed block first, and the record type exports from `@sublang/cligent/tmux-play` alongside the other record types; the follow observer treats the rendered reply as the pane write it is — TMUX-016, TMUX-020, TMUX-040, TMUX-050, TMUX-092
- `npm run smoke:release`: one local release-smoke entry point chaining the existing pre-release gates in RELEASE-010 order — clean `build`, `test:package` (clean-build package-output verification), `test:distributable` (packed-tarball consumer, launcher, Codex install-layout, and global-install onboarding acceptance), and `test:smoke` (built tmux-play CLI smoke) — so the pre-release checklist has a single command to run locally before tagging instead of replaying the gates by hand. The script adds nothing novel; it invokes exactly the checks RELEASE-010 defines — RELEASE-010

### Fixed

- The Claude Code adapter no longer terminates a resumed run on the CLI's internal continuation-repair result. When a run resumes a session whose previous turn ended with a dangling tool call, Claude Code first executes a synthetic no-op repair turn and emits a `result` message for it — success-classified, with no result text and zero token or tool usage — before the submitted turn produces anything; the adapter treated the first `result` as terminal, so it yielded `done` with `status: 'success'` and no `result` while the real turn was still starting, and its early return tore the SDK process down mid-turn, abandoning the submitted prompt. Downstream, tmux-play mapped that fake success to an `ok` call with no final text and the playbook engine failed the run. A `result` is now skipped — the stream keeps draining so the real turn's messages and its own `result` terminate the run as usual — only when all three of these hold: it matches exactly the no-op shape (success-classified, no error text, no non-empty `result` string, and zero input tokens, output tokens, and tool uses); the run was invoked with `resume`, because a fresh run cannot carry the repair turn and its zero-usage empty success is a genuine, if empty, terminal; and no `text`, `text_delta`, `thinking`, `tool_use`, or `tool_result` event has streamed yet in the call, because once the submitted turn has produced output an empty result is that turn's legitimate silent termination — consumers derive the final text from the captured events — not a repair artifact. A legitimate silent turn with nonzero usage terminates exactly as before, and if the stream ends after only the skipped no-op result, the existing missing-result path reports `error` honestly instead of a success with nothing in it — CLAUDE-003, CLAUDE-010
- A `callPlayer` / `callCaptain` call the Captain started without awaiting can no longer emit past its turn's terminal record. The runtime drained the dispatch queue as it stood when `handleBossTurn` returned, which covers the records an awaited call already emitted but nothing a still-running call had yet to emit, so a fire-and-forget call kept emitting after `turn_finished`: its `player_event` / `player_finished` (`captain_event` / `captain_finished`) records dispatched after the terminal record still stamped with the closed turn's id, and the tmux presenter painted player output after the turn had visibly closed and the ready prompt returned. The Captain run is now the turn's scope: when `handleBossTurn` settles the runtime closes admission first — from that instant every turn-scoped surface rejects, as it already did from terminal dispatch — then joins the calls the turn admitted, then drains, so each call's whole sequence lands ahead of the terminal record on the completed and failure paths alike. Closing admission before the join is what bounds it: a call presented afterwards, whether from an admitted call's own continuation or from an observer handling a record that drains later, rejects instead of joining the set being awaited, so the wait cannot be extended indefinitely. All four turn-scoped `CaptainContext` surfaces close together at that boundary — `callPlayer`, `callCaptain`, `setVisiblePlayers`, and `emitReply` — so a Captain need not reason about which one outlives its turn. Closing admission is a state of the turn rather than the end of it: the turn stays abortable through the join and drain, until the existing pre-terminal fence, so ESC, an external signal, and disposal unwind a call that outlives `handleBossTurn` exactly as they unwind an awaited one, and session-scoped `emitStatus` / `emitTelemetry` / `setVisiblePlayers` keep carrying the turn's id up to that same fence. The admission boundary is the runtime's resumption from `handleBossTurn` rather than that Promise's settlement, because a continuation the Captain scheduled on it runs before the runtime regains control; such a call is still admitted, and no implementation could make settlement itself the boundary — TMUX-016, TMUX-021, TMUX-022
- A `callPlayer` / `callCaptain` / `setVisiblePlayers` call the Captain started without awaiting can no longer terminate the host when its dispatch fails. Making fire-and-forget a supported style means the runtime both admits and joins such a call, so it owns that call's failure too, but the returned Promise carried no handler: an observer that threw while handling the call's own `player_prompt` / `player_event` / `player_view_changed` rejected it with an `ObserverDispatchError` nobody observed, and Node terminated on the unhandled rejection before the turn could unwind — turning an observer defect into a lost session. Every turn-scoped `CaptainContext` surface now marks its rejection observed while returning the original Promise, so a Captain that awaits the call still receives the error unchanged and one that never looks no longer takes the process down. `emitReply` was already covered, through the same guard `RecordDispatcher.emit` applies to the emission promise it owns — TMUX-016, TMUX-022, TMUX-081
- The terminal-last fence now covers every turn-scoped Captain surface. - Claude Code adapter's `canUseTool` callback now conforms to the SDK contract — it returns `Promise<{ behavior: 'allow', updatedInput? } | { behavior: 'deny', message }>` instead of `boolean | undefined`, so the SDK no longer rejects every Write/Bash invocation with a Zod validation error when `permissions` is configured
- tmux-play timer pane-border format strings use the correct `#{?cond,#[fg=A],#[fg=B]}` conditional shape (the previous `#[fg=#{?…}]` shape was rejected by tmux), and pane-title-keyed width computation uses the full `role · adapter` pane title so role panes get the right width budget for `glow` rendering

## [0.4.0] - 2026-05-17

### Added

- Markdown-rendered pane output via [`glow`](https://github.com/charmbracelet/glow) (IR-013) — text replies, captain summaries, and tool-result bodies render through the `glow` terminal Markdown renderer, so bold, code blocks, tables, lists, and word-boundary wrapping reach the pane intact
- Catppuccin Mocha theme on the tmux-play session (IR-012) — truecolor pane borders carry the adapter accent (claude/codex/gemini/opencode), speaker prefixes carry per-speaker colors (boss blue, captain mauve, role adapter accent), error/aborted status bodies carry red/yellow, and a dedicated tool lifecycle prefix grammar replaces inline tool noise: `tool>` (caller-colored) for invocations, `tool<` for results with outcome-keyed `✓` / `✗` / `·` markers
- Real-glow acceptance suite — integration tests exercise the presenter against the actual `glow` binary, covering well-formed prefixed output, payload trailing-blank preservation, and no-stacked-blanks between turns
- `query` priority key in the `tool_use` input summary — search/fetch tools (ToolSearch wrappers and similar) surface the query text rather than falling through to compact JSON
- DR-005 design record for per-adapter permission configuration (typed `PermissionPolicy` through `CligentOptions`; no implementation in this release)

### Changed

- **Breaking:** `tmux-play` requires [`glow`](https://github.com/charmbracelet/glow#installation) on `PATH` in addition to `tmux`; the launcher fails fast with an install-pointing error when it is missing
- **Breaking:** the `tool>` invocation prefix is colored by the caller's adapter accent (mauve for captain, the adapter accent for a role) instead of a fixed peach; `tool<` keeps the outcome palette (green / red / yellow)
- **Breaking:** the `overlay0` dim SGR around tool-result bodies is removed; styling is owned by `glow`'s code-block rendering inside a payload-safe code fence (fence width chosen as `max(3, longest_backtick_run + 1)` so embedded fences cannot terminate it early)
- Text bodies now appear on block completion rather than streaming token-by-token. Markdown is not a streamable format (a renderer cannot tell whether subsequent bytes belong to an open code fence until the closing fence arrives); this is the deliberate tradeoff for word-boundary wrapping and inline-style rendering
- Pane width budget reserves the visible `<who>> ` prefix when invoking `glow`, so prefixed first lines and indented continuations fit the pane without terminal-level rewrap
- Tool input summary truncation measures cells (CJK / emoji) rather than UTF-16 code units, so wide characters and surrogate-pair emoji never get split mid-codepoint
- README and `docs/tmux-play.md` Requirements lists updated to include `glow`
- CI acceptance job installs `glow` v2.1.2 before running acceptance tests

### Fixed

- TTMUX-039 truecolor probe scoped to the server-side option probe; the attached-client `#{client_termfeatures}` check required a PTY harness not yet in place
- IR-013 review-flagged rendering edges: outer-margin trim bounded to at most one leading + one trailing blank (fenced-code frames and payload edge blanks survive); tool body strips exactly one trailing line terminator (intentional trailing blank rows survive); blank-line detection uses visible content (real `glow` emits space-padded structural rows); fallback path skips the outer-margin trim when `glow` render fails
- Speaker-prefix coloring keeps the continuation indent uncolored across streamed text-delta chunks that split an SGR opener across the wrap boundary

## [0.3.0] - 2026-05-12

### Added

- `tmux-play` CLI and runtime — drives a multi-role agent session in a single tmux window with a Boss/Captain pane plus read-only role panes, YAML config discovery (cwd, then `${XDG_CONFIG_HOME:-~/.config}/tmux-play/config.yaml`), first-run default auto-create, and a programmatic API at `@sublang/cligent/tmux-play` for headless use
- Captain extension contract — third-party Captains ship as packages or local paths and receive a typed `CaptainContext` / `CaptainSession`; runtime owns every role and Captain `Cligent` instance
- Built-in `fanout` Captain (`@sublang/cligent/captains/fanout`) — broadcasts each Boss prompt to all roles in parallel and synthesizes a single Captain summary
- Unified `AgentOptions.reasoningEffort` (`minimal | low | medium | high | xhigh | max`) with per-adapter mapping (Claude `effort`, Codex `modelReasoningEffort`; Gemini and OpenCode ignore the field deliberately)
- Cell-aware soft wrap in the tmux-play presenter — width measured in terminal cells (curated EAW + emoji), ANSI escapes preserved as zero-width tokens across streaming chunks, per-writer resize tracking via SIGWINCH
- `<who>>` prefix presenter format with a two-space hanging indent that applies to every continuation line, including soft-wrapped ones
- Initial window geometry 240×67 (16:9 @ 1080p) with a pre-attach terminal resize request and session-scoped tmux hooks that hold the 4:6:6 column split across every window resize
- tmux-play acceptance suite — real-tmux 4:6:6 layout check plus end-to-end fanout drive across all four adapters, with a 2-attempt retry on transient upstream overloads
- New sub-exports `./tmux-play` and `./captains/fanout`

### Changed

- **Breaking:** package `bin` is now `tmux-play` (replaces `fanout`); the standalone `fanout` CLI is gone — the same fanout workflow runs as the default Captain inside `tmux-play`
- Codex adapter passes `skipGitRepoCheck: true` on every SDK thread so programmatic invocations against non-git working directories no longer hit the CLI's interactive-user safety gate
- Agent SDKs and CLIs pinned to last-green versions for reproducible CI

### Fixed

- Claude Code adapter now reads SDK `subtype` / `is_error` on the result message: `error_max_turns` and `error_max_budget_usd` preserve their protocol statuses, other `error_*` subtypes (and bare `is_error: true`) map to `status: 'error'` with `errors[]` surfaced as the message — repeated 529 overloads no longer report `status: 'ok'` with the CLI's "API Error" text as content
- Claude `reasoningEffort` narrowed to the SDK's `'low' | 'medium' | 'high' | 'max'` enum (`xhigh` collapses to `high`, `minimal` to `low`)
- Codex adapter unwraps JSON-encoded error messages, surfaces `turn.failed` before the SDK exec wrapper raises its generic non-zero-exit exception, and bumped to `@openai/codex-sdk` 0.129.0
- tmux-play launcher uses `split-window -l` for percentage sizing, focuses the Captain pane on startup, resolves symlinks in bin-entry detection, and hardens session error handling
- tmux-play presenter keeps the speaker prefix on the first nonblank line of every block
- `XDG_CONFIG_HOME` empty-string treated as unset (falls back to `~/.config`); a stderr warning fires when a legacy `tmux-play.config.{mjs,js,json}` is found in cwd
- Gemini adapter trusts the configured workspace and reports terminal errors in every done path
